# B60 — owner-validated Regenerate source (backend only)

The accepted reply itself is not a safe fork anchor: regeneration must retain the original player `EventId`, payload, media, observers and timestamp, while excluding every later accepted reply and side effect from the selected child world. B59 implemented the native player-input fork; B60 binds it to source evidence from a canonically accepted assistant receipt.

`SessionTimeline::fork_and_select_regenerate_source` takes a typed `RegenerateSource` with the expected character, accepted message `EventId`, accepted `RequestId` and original player `EventId`. Before changing the selected branch it checks the exact persisted selection/generation, parent head, latest visible assistant reply, accepted receipt matching the same request and message, a unique causal `ReplyTo` and matching `reply_to` payload, and the currently visible, earlier, addressed player input. Foreign, forged, hidden, superseded or stale source proofs cannot fork. B59's SQLite fork+selection commits under `BEGIN IMMEDIATE`, rechecking persisted selection and head in that transaction; after a competing append or A→B→A, the operation aborts without changing Timeline.

This is **not** accepted Regenerate. Neither B60 nor B59 connects the fork to `ChatApiState::send`, queue permit reservation, frozen preset and prompt capture, request registry, cancellation or generated-reply acceptance. Those stages must share one admission protocol and prove failure atomicity and late-result rejection before any presenter/Slint action. An in-process owner mutex alone does not establish durable cross-process request acceptance.

Proof cases: valid selected fork, original `EventId` and privacy retained, accepted downstream reply excluded, forged request/assistant/input/character rejected, missing causal link or matching payload rejected, hidden input or assistant rejected, superseding reply rejected, selection and head CAS, SQLite reopen and A→B→A. Other non-UI blockers: admitted request idempotency and rollback, provider cancellation, selected-branch effects/asset lifetime, cross-observer memory, concurrent independent writers and archive GC roots. No legacy/UI modifications.

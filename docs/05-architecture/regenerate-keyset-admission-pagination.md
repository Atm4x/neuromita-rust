# B72 — Snapshot-fenced admission pagination

`SessionTimeline::enumerate_regenerate_admissions_page(character, limit, cursor)` is a read-only, owner-internal recovery API. It does **not** dispatch a provider, reserve a permit, rewrite history, or make a previously unknown dispatch safe to retry. Public Regenerate remains disabled.

The page size is 1–128. An opaque process-local cursor contains the authoritative session, character, last **exclusive** child `BranchId`, fact `timeline_revision` and persisted active `TimelineSelection` (branch and generation). It cannot be deserialized from untrusted external input. Pages sort by canonical UUID branch ID. Every page checks the cursor's identity and both fences before source reads, and checks the fences again after classification. Any cross-owner write or active-selection A→B→A invalidates the cursor with `ConcurrentWrite`. Cursor reuse with another session/character fails closed.

SQLite discovers at most `limit + 1` admission branch markers per page using the authoritative JSON event table, indexed on `(regenerate_admission.character, branch_id, sequence)` and joined to `timeline_branches` for session and child/marker identity. The extra row only indicates whether another page exists; it is never emitted. Request-local classification and parent accepted-source lookup continue to use B71 indexed facts. An additional native index on `regenerate_admission.request` checks each emitted admission against **all** children of the same session, regardless of recipient or page. A duplicate anywhere in the session fails the page with `Conflict`, including if the second copy would appear on a later page. There is no mutable admission cache, cursor-local HashSet, new status table, or full `world(child)` reconstruction.

The transient repository uses the same sorted keyset contract over its in-memory branches; this is a bounded response, not a constant-memory transient scan. SQLite makes individual source pages bounded, although validating a page still performs request-local and canonical source reads for each result. `EXPLAIN QUERY PLAN` asserts the recipient expression index is selected; it is *not* a measured throughput benchmark. The index assumes the canonical native JSON serialization for the receipt's character/request fields. A direct out-of-band SQLite write bypassing the repository's revision/CAS protocol is outside the multi-page snapshot guarantee; runtime writes must go through the repository.

Tests cover page sizes 1/2, ordered exhaustion, empty and invalid pages, recipient and session crossover, SQLite reopen, other-owner append and selection A→B→A, duplicate request identity on another page, native query plan and archived-memory pagination. The existing archive tampering tests still verify imported forged recipients are rejected. Accepted source replies remain in the historical parent, not in the Regenerate child.

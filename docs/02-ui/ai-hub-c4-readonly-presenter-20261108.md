# C4 AI Hub: read-only Core catalog presenter

Parent: PR #279 (`ad9334cd0655ceccefd873b3165f9dc5b62e1c89`). Refs #37.

## Data ownership and event path

`DesktopRuntime` owns the active `SpeechModelCatalog` and produces `SpeechInventory` on startup and on `RefreshSpeechInventory`. `sandbox::apply` gives the **same** inventory to `voice`, `asr`, and `ai_hub` presenters. The Slint-independent `presentation::ai_hub_catalog::SpeechHubCatalog::from_inventory` projects the Core snapshot into typed view entries, five category counters and an error count. `neuromita-gui/ai_hub.rs` only adapts that read-only DTO to `HubModel[]` on the GUI event loop; neither Slint nor the presenter persists another catalog. Replacements replace the full list and its counters rather than accumulating stale rows. TTS and ASR can have equal plugin IDs without index aliasing because their categories remain separate.

The `AiHubPage` receives `ai-hub-entries`, `ai-hub-category-counts`, `ai-hub-discovery-warning-count`, and `ai-hub-can-refresh` through the existing `AppWindow` composition. The warning is an aggregate count only: invalid manifest values, filesystem paths and other raw discovery errors never enter card labels or tooltips. The refresh callback dispatches the existing `RefreshSpeechInventory` command only while an inventory source is available; it becomes unavailable on runtime stop. An audio-device enumeration failure reports the error but does **not** suppress independent speech catalog discovery.

## Truthful state model

`SpeechModelOption` supplies only `package_detected` and `verified_assets`, so the presenter distinguishes four states: `discovered`, `package-only`, `assets-only`, and `package-assets`. **None is worker-ready/model-loaded/inference-ready.** Real catalog entries must never receive the UI's demo-only `ready` status from these flags. A distinct read-only `RuntimeSnapshot` projection supplies the active TTS and ASR model IDs **only** when the corresponding service has `RuntimePhase::ModelReady` and an explicit `active_model`. The UI independently matches each active ID to that service's category, so identical TTS/ASR IDs do not alias. A merely running worker, pending model or failed/stopped lifecycle never marks a row loaded; `Update::Stopped` clears both active IDs. Loading a model does not enable an unsupported install or save action. Model backend, language, size, install location and settings schema are unknown at this boundary, and are not fabricated. The detail view is read-only with an explicit unconnected-schema message; Install/Remove/Save remain disabled.

Category counts are derived from the same inventory as the cards. Core/RAG/Else remain zero until a corresponding Core-owned inventory type and projection exist. Unknown backends do not match NVIDIA/ONNX/CPU selectors. Unrecognized/invalid plugin manifests are filtered by the Core catalog, not reclassified as valid in the UI.

## Verification boundary

`cargo check --locked --offline --features gui --bin neuromita-gui` and `cargo check --locked --offline --features gui --bin neuromita-gui --tests` validate generated Slint bindings and Rust types, **not** operation readiness or a functioning production installer. `cargo test --locked --offline --lib presentation::ai_hub_catalog::tests` executes the Slint-independent tests for category counters, duplicate IDs across categories, package/assets classification and replacement snapshots, without linking the memory-intensive GUI test binary. A separate async test scans real valid and malformed community manifests with the existing `SpeechModelCatalog` and proves that fixing a malformed manifest and deleting a model updates both counts and the warning. Runtime projection tests verify service scoping, `ModelReady` gating, and no identity inferred from `pending_model`. Renderer snapshots verify tab count badge alignment against title plus subtitle; the preview uses demo entries and is not the production catalog.

Remaining: Core-backed dynamic category metadata beyond speech, settings schemas/edit validation/save/revert, install/remove operation queue, runtime GUI E2E, stale selected-model fences, and Windows/macOS behavior. Runtime-loaded status is read-only and projected only from the existing Core-owned lifecycle snapshot; no new worker orchestration is added. The independent draft #262 is not merged into C4.

# C2: bounded live speech worker recovery

`LiveSpeechRuntime` now monitors the active `RunningAiApplication` on its existing settings-watch task. Every three seconds, `refresh()` observes OS child-process liveness; it never treats a Python handshake or an installation receipt as loaded-model readiness. When a selected service enters `Failed` with a concrete generation, the watcher may attempt recovery **at most twice per service and failed generation**. The retry budget is held in the watcher, not in `AiSupervisor` or the Python SDK. A settings-selection change resets that budget; successful recovery allocates a different generation. If both services belong to a shared process, a generation is handled only once in a polling cycle.

The recovery boundary reads the current persisted speech settings through `SettingsOwner` and prepares a *fresh* installed composition. Missing selected overlays, ambiguous executable plugin roots, unavailable locked Python or mismatched models fail without launching a substitute backend. The `RunningAiApplication` checks the new plan's exact Python host and process topology, and recovers **only** the failed worker's complete service group. In split topology a healthy ASR worker is not restarted when TTS fails. The supervisor requires that each selected service is `Failed` on the expected generation and that all reinitialized plugins report `model_ready=true` before publishing the new generation. A final selection/cancellation check runs after the private candidate has initialized and immediately before publication. If the guard fails, the candidate is terminated and the failed worker remains failed; the watcher later applies any actual user settings change through the established `reconcile` path.

A failed candidate cannot be shown as `WorkerRunning` or `ModelReady`. A hardware-profiled failed worker is still **rejected** by the software recovery path, not silently downgraded: hardware-verified recovery requires a separate explicit API and stored profile validation. Supervisor `recover_failed_composed` remains an explicit single-attempt primitive and performs no hidden retries. Watcher cancellation and application shutdown interrupt the scheduling loop, and changes to the saved speech selection invalidate the candidate before publication.

Tests cover per-generation retry exhaustion/reset, crash-to-recover with real mock TTS/ASR workers, healthy split ASR preservation, stale-generation rejection, invalid host plan rejection, and selection-change rejection. The existing shared-process recovery tests remain in scope. Validation still cannot certify full production voice inference, actual OS device-profile recovery or a complete Python 3.12 integration sweep.

**Remaining acceptance:** end-to-end installed managed-Python + persistent-settings retry tests; explicit user-facing exhaustion diagnostics and controllable retry/backoff policy; verified hardware recovery and cancellation of in-flight initialization. Until these are tested, issue #24 should remain open and C2 should not be marked fully complete.

# C4 — Core-owned admission for a pinned offline wheel stage

The existing `InstallPlanReview` is the only preview authority. `install_reviewed_wheel_stage` recomputes the current builtin Python install plan, its source revision, SDK revision, managed Python and the serialized review fingerprint before admitting a wheel-stage. It accepts a model identity, a stage ID and a backend identifier; it does not accept a package list, arbitrary wheel URL, wheel hash or command from Slint.

An optional `wheel-stages.lock.json` belongs beside the installed **builtin** plugin's `plugin.json`, `plugin.py` and `installplan.py`. It contains a bounded `stages` array. Each entry supplies `id`, `backend`, `package` (`name`, exact `version`), `wheel_file`, and `wheel_sha256`. The lock file is included in the reviewed plugin-source fingerprint, so adding, editing or deleting it invalidates any previous approval. The selected entry must match an existing `python_wheel` stage whose requirement is exactly `package==version`, and the requirement must be declared in the Python plan. Missing, duplicate, unpinned or inconsistent entries fail closed. No lock is synthesized for Fish Speech while its Triton wheel remains underconstrained.

`InstallApprovalGate` now holds an operation intent: legacy overlay or exact wheel stage/backend. A wheel permission cannot authorize an overlay, and any incorrect token, service, plugin ID, stage or backend consumes the one-shot permission. The GUI must request an explicit fresh approval before invoking the admission function. This PR exposes the Core operation; no GUI installation button is enabled by its presence alone.

The executor constructs its `ApprovedWheelStage` solely from the revalidated Core plan and builtin lock; it computes tool SHA-256 from the installed managed uv and Python files and uses the reviewed plan fingerprint for the immutable receipt. The wheel must already be present at `AIData/cache/wheels/<sha256>/<wheel_file>`; no network fetch or arbitrary shell is permitted. `LayerInstaller` copies the wheel into the operation-owned staging area, validates the copy before uv, executes `uv pip install --no-index --no-deps` against that snapshot, verifies the source and snapshot again, and removes the private copy before atomically publishing the receipt-bearing build-stage layer. If any verification fails, the stage is not published.

This is **one build-stage execution**, not a completed TTS/ASR installation: it does not publish a plugin overlay or model assets, activate a worker, mark an inference model ready, or satisfy later `source_build`/`runtime_jit` stages. A partial immutable stage is not a proof of a complete model. The current builtin lock trust boundary depends on trusted distribution and a source revision check; it is not a cryptographic signature of arbitrary community Python code. A fully durable orchestrator, cancellation, restart reconciliation, platform-specific locked wheel selection, native Windows and real CUDA/Triton kernel execution are separate acceptance requirements.

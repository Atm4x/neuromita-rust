# C4: verified offline Python wheel stage executor

This is a **limited real executor**, not a full Triton/source-build/runtime-JIT pipeline and not end-to-end TTS/ASR readiness.

`ai_runtime::build_stage::WheelStageInstaller` accepts an explicit `ApprovedWheelStage` with an exact package and version, plugin/source revision, backend, Python patch version, install-plan fingerprint, wheel path and SHA-256, and SHA-256 fingerprints for the selected `uv` and Python executables. It only admits an OS-matching `python_wheel` stage with `package==exact_version`. Dynamic selectors such as `triton-windows<3.4` are rejected until an approved exact-version wheel is selected. `source_build` and `runtime_jit` never pass the wheel executor gate.

The wheel must be present at `AIData/cache/wheels/<sha256>/<filename>.whl`; the executor does not download or select packages. The existing Core `LayerInstaller` performs an offline `uv pip install --no-index --no-deps` in a private `.staging-<uuid>` directory, verifies installed wheel distribution metadata, then publishes an immutable receipt to `AIData/build-stages/<plugin>/<revision>/<stage-id>` under the existing revision lease. Wheel contents are SHA-256 checked both before uv and before publication; platform, package identity and tool fingerprints are validated before creating the layer. Repeating the exact request reuses the installed layer. Source and target symlink chains inside AIData are rejected.

The pinned-plan SHA-256 is an input to this low-level primitive, **not** evidence that the GUI already enforced approval. The production `AiProductionInstaller` still refuses all nonempty `build_stages`. Integration must bind the lock to the Core-owned reviewed install plan/approval, validate the wheel against a trusted source, publish dependency layer selection and receipt atomically, then run a real model-specific GPU or inference smoke for `runtime_jit`. A successful wheel installation alone must never mark a worker/model/inference ready.

The Linux integration test creates an actual minimal wheel and runs the actual uv executable when `NEUROMITA_C4_TEST_UV` and `NEUROMITA_C4_TEST_PYTHON` are set. It verifies immutable publication, idempotency, and rejection after corrupting the source wheel; it does not exercise Triton or CUDA. No new crates, Cargo.lock changes, GUI dialogs, Python Legacy modifications, or persisted storage schema migrations.

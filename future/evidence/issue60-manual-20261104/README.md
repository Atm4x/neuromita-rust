## Покрытие и задержка

По критерию любого пересечения оба провайдера покрыли 21/21 размеченных интервалов.
Это не доказывает сохранение каждого слова: Earshot начинает сегмент en-1531
на 1158 мс позже ручного начала, а решение onset — на 1350 мс позже. В en-1548
есть конец, обрезанный на 604 мс; среднее двух концов этого клипа скрывало бы случай.

У Earshot 6 сегментов объединяют несколько ручных интервалов, у Silero — 7;
по одному ручному интервалу у каждого фрагментировано. Политика 448 мс тишины
может намеренно объединять близкие фразы, поэтому это не автоматически ошибка.
Однозначно сопоставлены лишь 8 пар у Earshot и 5 у Silero.

В этих подмножествах медиана решения onset — 126 / 188 мс, выдачи после естественного
конца — 498 / 550 мс (Earshot / Silero). Выборки разные: onset n=8/5, silence n=7/4;
это не парное сравнение одинаковых реплик. Среднее endpoint Earshot 310 мс включает
ранний обрыв и потому не является преимуществом скорости. EOF и неоднозначные
merge/split исключены из обычных timing means. Времена относятся к шкале PCM,
не измеряют wall-clock стоимость inference, ASR или ответ Миты.

## Воспроизведение и граница готовности

С явными локальными моделью и DLL, описанными в
`future/issue-60-review-fixes-20261104.md`, из корня worktree:

```powershell
cargo build --locked --offline --features vad-silero --example vad_ab
cargo run --locked --offline --features vad-silero --example vad_ab -- assets/eval/manifest.json direct 0.5 --validated-only
cargo run --locked --offline --features vad-silero --example vad_ab -- assets/eval/manifest.json wavekat 0.5 --validated-only
cargo run --locked --offline --features vad-silero --example vad_ab -- assets/eval/manifest.json silero 0.5 --validated-only
```

Полные per-fixture данные: [direct.json](direct.json), [wavekat.json](wavekat.json),
[silero.json](silero.json). Агрегаты TP/FP/FN, count и timing: [summary.json](summary.json).

Ручная проверка корпуса и строгий повторный A/B завершены. На этом малом наборе
Silero выглядит перспективнее для автоматического общения благодаря меньшему
числу шумовых сегментов и лучшему EN F1. Основной backend не переключён: остаются
lifecycle/интеграция, живой микрофон, тихая речь, hotplug и полная цепочка до Миты.
Issue #60 и PR по-прежнему не объявляются полностью завершёнными.

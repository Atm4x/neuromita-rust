# #60: владелец потока и разрешение записи

Ручной корпус и строгий A/B: [результаты](evidence/issue60-manual-20261104/README.md).
Сравнение с Python до изменений: [матрица](issue-60-python-gate-parity-20261104.md).
Эта ветка проверяет Rust VAD и правила потока до переноса физического захвата;
автоматическое включение микрофона в GUI не добавляется.

## Контракт Core

- ApplicationLifecycle выдаёт один SpeechInputHandler с захваченной арендой
  SpeechInputOwner до открытия устройства. Второй запрос получает InputBusy.
  Отсутствие активированного ASR выражено отдельно как Ok(None). Конфигурация
  GateConfig передаётся явно. Сам segmenter и native_vad_probe не требуют Python.
- Один обработчик владеет capture, буфером PCM, очередью сегментов, gate и маршрутом.
  Manual событие для сетевого маршрута должно совпадать с client UUID.
  Никакой переключатель режима не переносит сегмент другому клиенту.
- Automatic, Radio и PTT различаются. Radio включает автоматическую сегментацию
  на время аренды; за её пределами хранится только ограниченный prebuffer.
  PTT использует явный PttPolicy; без него переход в этот режим отклоняется.
  В PTT prebuffer не засчитывается в минимум голоса, хвост после release
  засчитывается. Режим с обязательным release после maximum не дробит удержание
  на повторные сегменты. Для automatic есть отдельный опциональный минимум голоса.
- Manual аренда привязана к UUID и возрастающему номеру нажатия. Renew продлевает
  только действующее нажатие. После mute, reset или истечения нужен release
  старого нажатия, затем новое. Обычный release сохраняет поколение ASR.
  Нажатие, отмена, отключение ввода, смена режима и истечение инвалидируют старые
  tickets, в том числе уже ожидающие ASR. Дедлайны срабатывают без новых PCM.
- Внешняя озвучка имеет ключ source/utterance, монотонный sequence для источника,
  ограниченный срок и хвост. Перекрывающиеся аренды не снимают блокировку друг
  друга. Отключённый источник не может снова открыть speaking lease. Размеры
  таблиц ограничены; переполнение — ошибка потока. Собственный playback
  дополнительно блокирует эхо до конца воспроизведения и ещё 400 мс; не отменяет
  ответ, который сам воспроизводится. Mute запрещает отправку кадров, а не
  автоматически закрывает процесс захвата.
- Live EOF и ошибка устройства завершают старый поток, отменяя незаконченный ASR.
  Повторное открытие — явный выбор и новая сессия. DShow выбирается по alternative
  identity; одинаковое отображаемое имя не задаёт fallback. Отложенная публикация
  привязана к старому Core и поколению и не допускается после их отмены.

## Граница интеграции

На upstream есть отдельная ветка `codex/speech-session-controller-20261104`
(`198074b5`), где GUI управляет захватом. Она не включена в этот PR. При сведении
её контроллер должен использовать тот же SpeechInputHandler, GateConfig, typed
ManualCapture с UUID/номером/renew и явный PttPolicy; не создавать второй
аудиогейт. Radio нельзя отображать как бесконечный PTT. Настройки UI и реальный
ASR runtime остаются у их существующих владельцев.

Политики Rust и Python различаются: Rust оставляет лимит сегмента 10 с,
базовый профиль A/B с 448 мс тишины, явное устройство и отсутствие авто-fallback.
Нужны аппаратные сценарии из [плана приёмки](issue-60-microphone-acceptance-20261104.md).
Прогон native probe не доказывает работу GUI или реальный ASR, а оценки A/B на
записях не измеряют задержку ответа Миты.

## Проверка 2026-11-04

- `cargo test --locked --offline -- --test-threads=1`: 557 прошли, 2 пропущены.
  Включая 53 аудиотеста, закрытие потока при ошибке устройства, блокировку
  второго владельца, отмену ASR при mute, таймер PTT и сохранение реплики после
  release. Отдельные тесты примера `native_vad_probe`: 3 прошли.
  В Windows явно задан `NEUROMITA_TEST_PYTHON` на установленный Python 3.12:
  системный alias `python3` дал ошибку запуска в первом прогоне.
- Пять регрессионных тестов локального микрофонного инструмента прошли:
  произвольная длина WAV, сохранность исходного PCM, формат, подробности ошибок
  Rust и отклонение неполного анализа. Синтаксис JS проверен `node --check`.
- Clippy all targets с `-D warnings` прошёл для default и `vad-silero`;
  форматирование и `git diff --check` прошли.
- Python ASR/RAG contracts: 8 прошли в существующем Python 3.12 окружении
  с NumPy 1.26. Whisper fixture подтверждает `vad_filter=False`.
- [Семь прогонов FFmpeg](evidence/issue60-capture-20261104/probe.json), без
  микрофона: тишина auto/PTT дала ноль сегментов, WAV ru-01 дал один сегмент
  auto/PTT на Earshot и один auto на реальном Silero; таймер остановил захват,
  некорректный источник вернул capture_error и ненулевой exit.
- Строгий A/B после сборки повторён при 0.5 на всех 18 клипах. Отчёты direct,
  wavekat и silero совпали с ручным прогоном во всех полях.

На физическом USB-микрофоне [подтверждено получение PCM](issue-60-microphone-acceptance-20261104.md)
через DirectShow для Earshot и Silero. При отсутствии PCM живой захват теперь
завершается ошибкой по таймеру. Затем пользователь самостоятельно записал речь
в браузере: [оба провайдера выделили по три сегмента](evidence/issue60-capture-20261104/user-microphone.md).
Это подтверждает browser capture → Rust VAD, но не живую DirectShow-сегментацию,
физическое переподключение USB или полную цепочку реального ASR.
Backend по умолчанию не менялся. PR подготовлен к ревью в указанном объёме;
issue #60 не закрывается автоматически.

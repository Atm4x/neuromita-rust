# #60: исправления после независимой перепроверки

Этот документ заменяет выводы о готовности из предыдущего handoff. Issue остаётся
открытым: существующие числа F1 получены на энергетических метках, а старые onset/
endpoint не были корректными измерениями задержки.

## Runtime и сборка

SileroScores::from_verified требует успешной инициализации через init_onnx_runtime.
Путь канонизируется и фиксируется на процесс; тот же путь допускает повторный вызов,
другая библиотека отклоняется. Конструктор больше не запускает поиск DLL через
ORT_DYLIB_PATH. Неудачная глобальная инициализация запрещает последующие попытки
подмены runtime в том же процессе.

Поддерживаемый runtime для этой приёмки — официальный Microsoft ONNX Runtime
1.24.2, Windows x64 CPU:

- файл lib/onnxruntime.dll из onnxruntime-win-x64-1.24.2.zip;
- источник: https://github.com/microsoft/onnxruntime/releases/tag/v1.24.2;
- размер 14 148 680 байт;
- SHA-256 114947d633e6844ce3c4b51ef6678f776628571d08a5763859c61642c8dcca9c.

Библиотека проверяется до загрузки. Это намеренно узкая поддержка проверенной
сборки, не обещание работы с произвольными DLL или другими платформами. Телеметрия
ORT отключена. Другой код процесса также не должен инициализировать ort независимо
от владельца audio runtime; подмена уже загруженного стороннего ORT не поддерживается.

В .cargo/config.toml задан отсутствующий локальный SILERO_MODEL_PATH с force=false.
При сборке **из корня репозитория**, как требует HANDOFF, без явно выбранной модели
Wavekat завершается ошибкой до сетевой ветки. Переменная окружения оператора может
задать абсолютный путь к проверенной модели. Vendor не патчился. Запуск Cargo из
чужого каталога через --manifest-path без загрузки этого config не входит в этот
контракт: Cargo не читает config по пути манифеста автоматически.

Модель и runtime в репозиторий не включаются. Перед запуском:

```powershell
$env:SILERO_MODEL_PATH = 'C:/absolute/path/silero_vad.onnx'
$env:NEUROMITA_SILERO_MODEL = $env:SILERO_MODEL_PATH
$env:NEUROMITA_ORT_DLL = 'C:/absolute/path/onnxruntime.dll'
```

## Сегменты

Максимум должен быть кратен 256 сэмплам — единице capture. Конфигурация, где
onset/pre-roll с компенсацией задержки провайдера больше максимума, отклоняется.
Это предотвращает выдачу 768 сэмплов при max=512 и 512 при max=257, воспроизведённую
в ревью. Проверенные обычные конфигурации не теряют onset и не дублируют кадры на
разбиении непрерывной речи.

Сегмент хранит абсолютные offsets PCM, момент подтверждения onset, момент выдачи и
причину завершения: Silence, Maximum, Release или Eof. Поэтому pre-roll не делает
решение мгновенным в отчёте. При reset начинается новая временная шкала, подавление
playback сохраняет часы capture.

Drain после EOF учитывает явную отмену и дожидается завершения отменённого worker.
По дедлайну worker также отменяется и собирается до возвращения ошибки.

## Эксперимент

Оценщик различает неизвестные, эвристические, ручные метки и подтверждённый шум.
Непроверенные шумы нельзя считать ground truth; события сегментации для них
сохраняются, метрики качества подавляются. Строгий режим требует подтверждённых
меток. Интервалы за пределами WAV отклоняются.

Границы PCM имеют знаковую ошибку: ранний обрыв не становится нулём. Отдельно
измеряются момент решения onset и момент выдачи после тишины. EOF-censored и
принудительные завершения не выдаются за естественные endpoints; слияния и
фрагментация считаются отдельно от покрытия.

Ручная разметка и микрофонная приёмка по-прежнему не выполнены. Победитель backend
не выбран. Старые таблицы сохраняются как история предварительного эксперимента,
а не как доказательство качества или готовности.

## Проверки после обновления main

База обновлена до upstream/main `095a4e71` (merge `c811af93`). В тестах использован
актуальный канонический CharacterId::Crazy. Команды выполнялись из корня worktree,
с `--locked --offline`, Rust 1.99 и локальным vendor.

| Проверка | Результат |
| --- | --- |
| Полный `cargo test` после merge main | 546 passed, 0 failed, 2 ignored |
| Аудиотесты после исправления часов playback | 43 passed, 0 failed |
| Аудиотесты с `--features vad-silero` после финальных правок | 46 passed, 0 failed, 1 ignored |
| Отдельный ignored Silero inference-тест | 1 passed, 0 failed |
| Clippy `--all-targets -- -D warnings`, default и vad-silero | оба прошли |
| `cargo fmt --all -- --check` | прошёл |

Полный общий прогон предшествовал последней локальной правке часов playback;
после неё аудиотесты повторены отдельно. Inference-тест загружает реальную модель
и DLL, проверяет reset состояния и offsets, повторный вызов с тем же путём и
отказ от другого runtime. Он не доказывает качество распознавания человеческой речи.

При отсутствующем SILERO_MODEL_PATH сборка с vad-silero завершилась ожидаемой
ошибкой отсутствующего локального файла. Даже с SILERO_MODEL_URL, направленным
на недоступный локальный порт, ошибка возникла до сетевой ветки dependency build.rs.

`tools/vad-annotator.html` и `issue-60-manual-annotation.md` дают локальный процесс
ручной разметки. Проверка JS через Node и DOM-stub: синтаксис и 169 утверждений,
включая 18 настоящих WAV, ограничения интервалов, частоту 16 кГц и сброс статусов.
Реальное отображение и воспроизведение в браузере этим не проверялись. Сам инструмент
не выполняет ручную проверку корпуса и не превращает эвристические метки в ручные.

Новый прогон всех трёх провайдеров на пороге 0.5 опубликован в
`evidence/issue60-review-20261104/`. Direct и Wavekat Earshot дали побайтово
одинаковые JSON. В каждом отчёте 12 heuristic и 6 unknown клипов; у unknown поля
качества равны null, но сырые сегменты сохранены. Для шести unknown записей Earshot
выдал 9 сегментов (10.128 с), Silero — 1 (0.768 с). Это наблюдения о выдаче
сегментатора, а не доказанные ложные реплики. Пока отсутствие речи не проверено,
нельзя объявлять качество на шуме или выбирать победителя.

`--validated-only` ожидаемо отказал с перечислением всех 18 непроверенных клипов.
До ручной разметки нельзя заполнить корректную итоговую таблицу «до/после».
Старая разметка и исторический отчёт сохранены, исходные WAV не изменены.

# Cycle60 — Opt-in Documents evidence at generation admission

The production Request owner now supports **opt-in, character-scoped, source-verified lexical Documents** evidence. A new `DocumentGenerationSettings` section lives in the ordinary persisted `AppSettings` and is read from the existing immutable admitted request settings. Its initial/default value is an empty `sources` map, so existing generation behavior is unchanged. Any previously serialized settings without this section deserialize with Documents disabled. No UI, LLM plugin, index writer or implicit source registration was added.

The section contains `sources: CharacterId → {root, index}`, `max_results` (1–4; default 3), and `max_content_chars` (64–800; default 500). A trusted local Settings API caller can replace or edit this typed section. Both paths must be absolute and syntactically canonical (without `.` or `..`), and the derived index must not be inside the source root. The operator must first build a **new** index using `neuromita documents build --root ABSOLUTE_CHARACTER_ROOT --character Kind --index NEW_ABSOLUTE_PATH`; the index is never rewritten automatically when a source changes. Removing a character entry disables that source. No global or cross-character default exists.

The `MessageHandler` retrieves one exact configured source only for the request's admitted `CharacterId`, after its existing Memory/History selection and before invoking the generation provider. `knowledge::document_generation` depends only on its own root/index paths, character and query, keeping app settings ownership at the top-level handler. This selection calls `document_index::search_verified`, which independently validates root, index, exact character/source identity, original UTF-8 bytes, bounded file inventory, deterministic chunks and SHA-256. Query text is bounded at 512 Unicode scalars; selected chunks use existing native lexical fusion, never substitute an unavailable semantic model. Results are rendered as bounded JSON records (`character`, relative `source_path`, `source_sha256`, `chunk_index`, `content`) inside an explicitly marked **untrusted data** evidence block. No absolute source paths, configuration secrets or provider credentials are exposed as provenance.

Errors are terminal to that generation attempt, not a request to fall back to other retrieval modes. A missing/corrupt/stale index, changed source, foreign scope, invalid query, filesystem refusal, or task failure prevents provider invocation. An empty valid corpus or query with no hits contributes no Documents excerpt. Settings are captured at request admission, so later enable/disable edits do not silently alter queued operations. Blocking filesystem checks run in a dedicated thread; no Timeline storage locks or new canonical store are involved. Existing Memory/History evidence and their failure semantics remain unchanged.

Acceptance evidence: real in-process ApplicationLifecycle/controlled-provider integration covers opt-out, character isolation, prompt provenance, stale source rejecting generation without provider contact, and settings changes after admission while a prior request blocks the queue. Old settings JSON defaults and invalid source/path/limit values have dedicated tests. Existing operator CLI tests still cover source/index corruption, Unicode chunking, no-clobber publishing, and scope violations.

Limitations: only bounded `.md`/`.txt` lexical Documents, with prebuilt disposable index. No default user-facing document picker, PDF/Office extraction, native semantic/vector Documents backend, model reranker, user-visible citation display, independent author authentication, OS-level exclusion of concurrent file writers, or recoverable cross-owner data snapshot. This is a genuine generation-integrated R6 slice, **not full R6 acceptance**; formal R6 OPEN, R7 OPEN, M7/D5 OPEN and matrix remains 16 PASS / 4 PARTIAL / 6 OPEN.

# Scoped user-variable transfer (Cycle 28)

This format is **not** a full application backup, SessionArchive, MemoryRecord bundle or World.db export. It transfers only values from `character_variables_at` for one selected character on the currently selected canonical Timeline branch. It excludes computed state (`attitude`, `boredom`, `stress`, `ACCEPTED_REPLIES`), conversations, memories, game variables, settings, user assets and other characters.

The trusted local CLI exposes `/knowledge variables export PATH`, `/knowledge variables preview PATH` and `/knowledge variables apply TOKEN`. The export file is published with the existing private-stage, fsync, atomic no-clobber filesystem protocol; an existing path is never overwritten. A variable archive is a distinct JSON object with `format="neuromita-user-character-variables"`, `version=1`, `scope="user_variables_only"`, a source-character label, a string-to-JSON-value variables map and a lowercase SHA-256 digest over deterministic serialization of those five semantic fields excluding the digest. The checksum detects accidental corruption; it is **not** an authentication mechanism and cannot prove the source character.

The transfer uses the existing canonical `CharacterVariablesChanged` fact and its `validate_character_variables` policy, not an independent persistence store. Keys are unique and validated, including rejection of reserved computed names. At most 64 total variables can be present after import, each value's JSON representation is bounded to 4096 bytes, and the entire archive is capped at 256 KiB. Import is **add-only**: identical name/value pairs are no-ops, conflicting names with different values reject the entire preview, and missing names are inserted together as one guarded Timeline append. No overwrite, removal, silent coercion or fallback is performed. Empty archives are valid and do not change the Timeline.

The private `VariableImportPreview` holds an immutable character-owner selection, anchor and snapshot. Only explicit confirmation against the exact character allows dispatch. Cancellation before dispatch, character switch, reset, branch change and intervening Timeline events reject an old preview; a commit race is rejected inside the same guarded append. If the provider exits before commit, there is no partial variable import. SQLite reopen must produce exactly the same canonical user variables. Once an apply has been dispatched, the CLI does not promise cancellability.

Variable archives and retained-memory archives are **separately confirmed operations**, **not** an atomic combination. A future broad export/import must obtain Agent B's authoritative SessionArchive capability for history and design a single cross-owner preflight/commit policy. Never synthesize Python history rows, write SQLite directly or claim that copying these two files restores full character state. D4, D5 and M7 remain OPEN.

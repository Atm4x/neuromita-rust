# R7 failure and provenance contract — Agent A Cycle45

**Acceptance status: OPEN.** R7 requires the full user-visible failure matrix, including missing/corrupt index, timeouts, partial sources, and model/provider failure. Passing this targeted provenance slice is not sufficient to mark R7 PARTIAL or PASS without the missing workflows.

## Canonical boundary

`MitaView` is the single owner of visible History. The retrieval result is a derived candidate, not a new authority. At final `render_history_evidence` / `render_archived_history_evidence` admission, the selected character, branch, Timeline prefix, archived `HistoryWindow`, original `EventId`, User/Assistant role, exact source metadata (`message_id`, `sequence`, `learned_at`, `role`, `branch_id`, `through`) and **exact Unicode character-budgeted content** are reconstructed from the current `MitaView`. The renderer also rejects Selected-vs-hit-count inconsistency, duplicate `EventId`, missing/duplicate/invalid retrieval methods and nonfinite scores. This avoids treating a valid prefix of a message as a verified complete quote or accepting metadata spoofing after fusion/reranking. A validation error is `HistoryEvidenceError::InvalidEvidence` or `StaleSelection`, not alternate retrieval.

`history_retrieval::hit` already owns the canonical metadata format; the renderer compares against it instead of introducing a second serialization contract. Legitimate search results truncated at the same `max_content_chars` budget remain valid. The renderer does not modify Timeline, change visibility, allocate a persistent index or perform model calls.

## Cycle45 non-GUI recovery workflow

The terminal entrypoint now accepts explicit local commands `/ai worker status` and `/ai worker restart SERVICE EXPECTED_GENERATION_UUID`. Status reads the existing `RuntimeStatePresenter::refresh_status` and exposes each selected service's exact generation, phase, model identifier and original failure reason. Restart dispatches directly to the already existing `ApplicationLifecycle::restart_failed_ai_worker` owner operation. The terminal input is local standard input, not an unauthenticated HTTP mutation endpoint. No worker is restarted by observing status; the operator must supply the exact failed generation UUID. A changed generation, healthy service, missing plan, and unsafe hardware selection still fail in the owner. The returned generation is cross-checked against a fresh source-owned `ModelReady` status before reporting success.

A new real Python subprocess integration fixture exercises the previously missing full composition: `ApplicationConfig.ai_runtime` + `AiKnowledgeSelection` → Request's archived History semantic embedding → actual mid-infer Python crash → `TextGenerationFailed` **without reaching the LLM** → explicit `ApplicationLifecycle` recovery with source-owned failed generation → retry through Request → **original canonical archived `EventId` and content**. This test is a deterministic Python plugin and mock LLM observer; it is not a claim about neural model quality. The terminal command parser separately checks strict generation/service parsing. This explicitly avoids a second supervisor, generic fallback, worker watchdog or automatic retry.

**Important operational boundary:** The standalone default `neuromita` terminal launcher currently does not configure Python `ApplicationConfig.ai_runtime` itself. For that default invocation the command reports unconfigured/stopped services and rejects recovery. It becomes effective when the application is created with an explicit prepared Python AI runtime plan. Do not describe this as automatic installation/configuration or a universally available end-user recovery workflow.

## Unclosed required R7 work

1. **Documents R6** has no accepted owner/index/version/citation boundary, so corrupt/missing document-index, rebuild, partial document batch and recovery cannot be tested end to end. Do not emulate a persistent document index from ephemeral History FTS5.
2. **Timeouts, process crash and cancellation:** Cycle41 proves actual Python embedding and reranker subprocess `infer` timeouts through the **production adapters** to the Request API; Cycle43 additionally proves both actual worker process crashes mid-infer, with no LLM invocation, original failure preserved, split-worker isolation and successful same-application explicit restart/retry. Stock `AiKnowledgeSelection` embedding+reranker composition is proved separately. These tests use deterministic mock plugins (no real model inference), and the fault-injected run uses direct adapter injection instead of a live `AiKnowledgeSelection` supervisor reference. **Automatic restart, production model timeout acceptance, terminal setup with a selected Python AI plan and complete end-user recovery remain unverified**; no new timeout default has been introduced.
3. **Partial multi-source failures** require an explicit all-or-nothing/degraded-results policy accepted by the user. Do not invent lexical fallbacks when one semantic source fails.
4. **Cycle42 AI Engine status and existing Sandbox/terminal error text** are exposed through the current presenter/renderer. Cycle43 independently executes the actual AI Engine **component** on a headless Slint renderer, with failure and recovery snapshots, but does not execute the full AppWindow binding tests due to GUI test-binary codegen OOM. Full real-model GUI/CLI interaction, a user-triggered restart/retry from the Desktop Presenter (backend owner operation is now available), and corrupted derived-state recovery remain unproven.

The current implementation remains a strict, local, source-owned retrieval engine with **no parallel mutable Memory/History index**, no implicit mode change and no unrelated Legacy modifications.

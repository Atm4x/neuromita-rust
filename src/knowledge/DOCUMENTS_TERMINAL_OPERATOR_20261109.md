# R6 — Explicit trusted Documents terminal operator (Agent A Cycle65)

The stock interactive terminal, while `ApplicationLifecycle` is running, now exposes `/documents` operations over the existing `DocumentRevisionApi` and `SettingsApi`. The offline `neuromita documents reindex` remains **prepare-only**: it creates an immutable derived revision and prints `DocumentRevisionReceipt` JSON to stdout. For example, an operator can redirect that JSON to an absolute local `receipt.json` path. The terminal never modifies source documents, index files or the settings JSON directly.

Commands:

- `/documents status Crazy` checks the selected source strictly and returns an error if its index or canonical files are unavailable. `/documents inspect Crazy` (or another canonical `CharacterId`) reports the current global settings revision, disabled/ready/unavailable state, index fingerprint and document count, and whether that same settings revision is confirmed persisted. It never prints document contents or absolute source paths.
- `/documents activate Crazy EXPECTED_SETTINGS_REVISION /absolute/receipt.json` reads one bounded regular receipt file (max 8192 bytes; direct symlinks rejected), enforces the explicitly named character and source/index fingerprint via `DocumentRevisionApi::activate`, and uses its existing `SettingsApi` CAS. Quoted absolute filenames containing spaces are accepted. Only after `SettingsApi::flush()` and an independent active-source recheck does the terminal report a durable activation.
- `/documents deactivate Crazy EXPECTED_SETTINGS_REVISION` removes only that character's source mapping through the existing settings CAS. Durability is confirmed by `flush()` and a current snapshot check; the other characters are untouched.
- `/documents retry-save EXPECTED_SETTINGS_REVISION` requires a current settings revision match, invokes `SettingsApi::retry_save()` and awaits `flush()`. It persists **all pending settings sections**, not only Documents. A concurrent change is reported, not silently treated as the requested revision.

The expected settings revision is obtained from `inspect`; stale CAS, missing/forged receipts, mismatched characters and invalid sources are rejected without mutation. Source/index verification is intentionally performed away from the Tokio event loop. A failure **after** a successful in-memory CAS is explicitly described as **not durably saved**, with the current revision needed for manual retry. A subsequent process restart reads only the last durable settings revision. The index remains disposable; the actual `.md`/`.txt` files are the only authoritative document content.

**Constraints:** This terminal workflow needs a normally running application and trusted local terminal input, so it is not an unauthenticated HTTP endpoint, a GUI picker or an offline settings import tool. A pathname may be replaced after receipt validation, and ordinary filesystem-level concurrent source changes cannot be prevented by the optimistic fingerprint check. The settings repository's durability guarantees remain those of `SettingsApi`/`JsonSettingsRepository`; a successful `flush` is not a general power-loss guarantee for external files. R6 is not yet fully closed: no PDF/Office ingestion, semantic document retrieval, full UI document selection or end-to-end cross-owner source controls.

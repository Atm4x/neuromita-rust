# Typed Timeline message content (agent B2)

Canonical Timeline events store ordered `content` parts as JSON, never embedded binary bytes. `TimelineMessagePart` accepts `text`, `image`, `audio`, `file` with a typed `TimelineAssetRef`; historical string content and `{ "text": ... }` parts remain readable. All other part shapes, extra fields, and contradictory MIME categories fail explicitly. No secondary history is created. A message's role, speaker and external identity are retained in its `VisibleMultimodalMessage`, which is derived only from a fixed `MitaView`.

`generation::multimodal` exposes pure codec boundaries, taking a caller-supplied `MitaView` and injected `TimelineAssetStore`. Gemini supports JPEG/PNG/WebP/GIF and WAV/MPEG/Ogg/FLAC as bounded `inlineData`; OpenAI Chat Completions and Responses support input images only. Unsupported media, assistant-side images for OpenAI, missing or corrupt files, and oversized requests fail closed. The total binary input cap is 16 MiB and per-part cap is 8 MiB. These are serialization limits, not a guarantee of model-specific quotas or server acceptance.

**Status / live integration:** The generation request now receives an optional injected `TimelineAssetStore`. Both Gemini `generateContent` and OpenAI Chat/Responses resolve binary parts strictly from the current `MitaView` and attach them to the corresponding EventId's historical message after provider transformations. Text-only world events, memory, working state, game state, reminders, current task, system policies and native tool history keep their existing locations. If message transformations merge, reorder, rewrite or ambiguously reproduce the media-bearing history, the provider request is rejected before network transmission; no fallback to text-only generation is permitted. Unsupported MIME, absent/modified bytes and missing configured store also fail closed. Observers receive a redacted media payload marker instead of base64 request contents, so diagnostic tracing does not retain user binary data. Only supported image/audio codecs are allowed; `file` is not silently converted. File ingress into Timeline remains a separate action, not an implicit generation trigger. Archive-aware GC is still pending; the app's global portable data root remains Agent D's responsibility.

Representative regression: `cargo test --locked --offline --test timeline_assets --test timeline_multimodal --test timeline_conversation --test timeline_mitaview --test openai_protocols`. Fixture coverage includes historical prefixes, fork/hide, cross-character visibility, media order and codec dialect, missing/tampered bytes, and explicit unsupported formats.

### Streaming provider boundary (B43)

Loopback HTTP/SSE regression now executes actual Gemini, OpenAI Chat and OpenAI Responses provider transports using an identical `MitaView` fixture. It checks that a selected message's mixed text/image/text parts reach the outbound provider JSON in their original order exactly once, even when a private image belongs to another character and a previously visible image was hidden. Neither those inaccessible bytes nor their text is sent to the provider or recorded in the prepared prompt. Fragmented SSE responses are decoded to the structured response; the request observer receives only a redacted outbound media marker, and response/stream observations contain no original media bytes. A valid content-addressed zero-length image fails before any SSE HTTP request or `request_prepared` event. This is deterministic local transport evidence, **not** a claim about any paid remote provider or the still-unproven GUI, cancellation, tool-continuation and complete production acceptance matrix. It does not change GC or authorize deleting any attachment.

### B44: streamed tool continuation, cancellation and request preview

The live provider boundary now has real two-request SSE loopback regressions for Gemini, OpenAI Chat Completions and OpenAI Responses: one source EventId's image is included once per outbound request, its text/image/text order and observer privacy survive the native calculator tool follow-up, and provider-native tool replies are supplied on the second request without new Timeline facts or duplicate images within that request. A separate cancellation test drops an incomplete streamed provider future after its first observed delta, verifies the HTTP socket closes and no result is published. RequestRecord retains the completed tool indicator while waiting for the next turn, then removes it when the next stream's first text arrives; cancelled requests clear provisional text and tool state. A pre-fix regression demonstrated the stale completed tool overlay. These checks do **not** claim proof of the full UI acceptance, every character/session switch, Windows behavior or provider-side cancellation guarantees.

### B45: historical HTTP snapshots and captured turn agreement

A local streaming HTTP test now exercises the **same source event** as originally observed, edited, and preserved in a fork sibling; it also generates after that event is hidden and after the character's context reset. Every captured branch/through snapshot is sent separately through Gemini, OpenAI Chat and OpenAI Responses. Each actual outbound body contains exactly the authorized image revision, in its canonical part order, or no image at all after hide/reset. Neither the other revision nor the other character's private media/text is sent. Diagnostics never retain binary data, and none of these provider calls writes a Timeline fact. Historical reads deliberately remain historical: a later edit cannot mutate an already captured, independently selected old prefix.

The generation dispatcher now verifies **before invoking any provider** that `CharacterContext.character_id`, `ContextAnchor`, `TimelineTurn` and the immutable `MitaView` all describe one consistent observer, branch and cutoff. A mismatched turn/anchor previously reached the provider transport; a red/green regression now rejects six inconsistent input shapes for each of the three providers before any HTTP connection, provider observation or response. This is a static **request-input consistency** check, not a replacement for the RequestHandler's dynamic selection/context-epoch cancellation and atomic acceptance guards. An older but internally consistent captured historical context is not retroactively rewritten or prohibited by this check. Real Slint callback behavior, concurrent live character-switch races and full remote provider acceptance are still separate unproven gates.
